# Plan 7: LLM editors and offline comparison

**Status: draft.** Start from the style catalogue in [Plan 4a](04a-styles.md), the story types from [Plan 4b](04b-story-mining.md), and the authored variants from [Plan 4c](04c-variant-drafting.md). Verify LLM editing offline before exposing it in [Plan 5](05-live-integration.md).

## Goal and success criteria

Add an optional LLM editorial mode that shares the heuristic editor's evidence, language styles, series, and publication rules. Compare the editors from the same starting state and show where model editing improves a real issue, such as combining several related research developments into a concise roundup. A failed model call still yields the heuristic result for the same check, and switching modes preserves the reader's archive, votes, and series history.

## Current state

`editorial/check.ts` prepares a check and selects authored stories even when the saved `llmEnabled` preference is set. `editorial/presentation/validation.ts` checks completed issues, and `contracts/publication.ts` currently records only heuristic decisions. `replay/session.ts` and `replay/store.ts` own replay orchestration and commits. Vox Agents already has provider and prompt conventions in `agents/{models,runtime,prompts}/`; verify that the chosen evaluation path works from standalone replay before building on it.

## Ordered work

1. **Prepare the editor input and proposals.** Use `editorial/check.ts` to share projected developments, eligible candidates, prior installments, feedback, and presentation choices with a constrained adapter in `editorial/llm.ts`. In LLM mode, include eligible model-only templates using the existing `llmOnly` setting; preserve the heuristic filter. Pass only the relevant evidence and owner-supplied guidance for the available voice, stance and genre tags. Use a bounded history and context budget and the existing Mustache prompt convention. Apply provider selection, cancellation, and token accounting through the existing evaluation path. The model receives prepared data and can return proposals only. Define the proposal schema in `editorial/proposal.ts`: candidate selections, merges, prose, and optional ad hoc angles with typed subjects and supporting references. Require one voice, one stance and one genre ID for each proposed article.
2. **Validate before publishing.** Check proposed subjects, evidence IDs, reported quantities, page and layout eligibility, a registered tag for each of the three axes, reading length, and canonical series and item identity. Existing candidates retain their computed importance; mergers use the existing maximum rule, and ad hoc importance cannot exceed the allowed range or the highest supporting trigger. Require ad hoc proposals to use observable evidence and recognized subject and angle identities. Produce the final issue through the shared presentation path. For an invalid item, use an eligible authored fallback or omit the item. For a failed or unusable response, run the heuristic editor on the same prepared check. Extend the decision schema in `contracts/publication.ts` to record the requested and accepted editor and any fallback. Commit one accepted result or skip; cancel obsolete checks before committing. Preserve archived text and existing votes across mode changes.
3. **Add reproducible comparisons.** Extend replay with an evaluation runner, versioned records, and server entry points using the existing routes and store. Choose a few recording segments from different eras as the comparison set and record them with the run. Fork the same evidence sequence and initial state into isolated heuristic and LLM runs. Have the runner apply one scripted set of votes to both runs through the replay feedback path at fixed cutoffs; match articles by subject and series or canonical identity across runs. Record unmatched votes as evaluation differences. Capture inputs, model and configuration, proposals, accepted output, fallbacks, token usage, and latency. Run a separate mode-switch scenario on one archive to check continuity as series histories develop.
4. **Read and assess the results.** Review the model's issues alongside the heuristic issues for useful selection, merging, brevity, continuity, voice, and supported claims. Inspect prose against the evidence: a valid reference establishes traceability, and the reviewer still needs to check that it supports the claim. Document important differences, failures, and cost in the [evaluation guide](../../../developers/vox-agents/newspaper/evaluation.md). Carry the accepted fallback and editor behavior into Plan 5.

## Verification and scope

Use a controlled adapter to exercise valid proposals, missing or unknown style tags, unknown subjects, unavailable evidence, inflated quantities or importance, duplicate series, malformed output, provider failure, and cancellation. Verify item and whole-check fallback, including omission of a model-only item when no authored fallback applies. Verify that the disabled setting makes no model calls and switching modes continues the same canonical series, votes, and prior articles. Include an ad hoc angle that a matching authored template can continue. Use a real configured provider for the reading comparison and separately record cost and latency. Run focused editorial, replay, and contract tests, then `npm run build:all` and `npm run test:all` at handoff.

Catalogue and style authoring belong to Plans 4a to 4c. Periodic checks and the in-game controls for opening the latest issue belong to Plan 5.
